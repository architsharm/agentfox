# Secrets detection: investigated, blocked on dataset access

**Outcome, stated plainly**: `src/agentfox/guardrails/detectors/secrets.py` (known-format regexes + entropy-gated generic fallback — a genuine classifier, unlike F2/F4's declared systems) is exactly the kind of mechanism a public labeled dataset *could* stress-test well. Both datasets `docs/evaluation/dataset-sourcing.md` sourced for it are real, on-topic, and license-compatible in principle — but neither is a same-day fetch, and both blockers require a human decision this pass doesn't make unilaterally:

- **[Samsung CredData](https://github.com/Samsung/CredData)** (harness: Apache-2.0) — 4,583 true / 73,842 candidate secret lines from 297 real GitHub repositories. The harness code is clearly licensed; the underlying *content* is each repo's own license, individually. Committing even a filtered slice of this into this project's public `benchmarks/secrets/data/` would mean redistributing scraped code from 297 differently-licensed sources under one umbrella — `docs/evaluation/dataset-sourcing.md` already flagged this exact risk ("needs a human license call before use") rather than treating it as resolved. That call wasn't made unilaterally here, consistent with how this project treats every other license ambiguity found this session (AmbiFC, ALCE-data — both held back for the same reason, see `benchmarks/source_authority/README.md`).
- **[SecretBench](https://github.com/setu1421/SecretBench)** (MIT) — 15,084 true / 97,479 candidate secrets with rich per-secret metadata (`entropy`, `is_template`) that's close to purpose-built for validating an entropy-threshold design like this detector's. Access-gated: requires contacting the authors and signing a data agreement, which isn't a same-session fetch regardless of license terms.

Also checked and rejected during this pass: a broader Hugging Face search for alternative secrets-labeled corpora turned up nothing usable — the closest hits were either NC-licensed (`Podric/prowl-secrets-corpus`, CC-BY-NC-4.0 — excluded by this project's own license bar) or synthetic agentic-workflow data with no true/false secret ground truth at all (`rmems/secret-scan-remediation-trajectories` — remediation-planning trajectories, not a detection corpus).

## What would unblock this

A human call on CredData's per-file provenance risk, or initiating SecretBench's data-agreement process — both real next steps, neither completable inside this benchmarking pass. Flagged here rather than silently skipped.

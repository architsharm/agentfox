# F2 — source authority & provenance: investigated, not directly benchmarkable

**Outcome, stated plainly up front**: none of the three datasets `docs/evaluation/dataset-sourcing.md` sourced for F2 (HALLMARK, CRED-1, ALCE) test the mechanism `src/agentfox/provenance.py` actually implements. This is the same class of legitimate, disclosed outcome as `benchmarks/action_safety/README.md`'s ToolEmu investigation — a real finding from checking the fit carefully, not a shortfall from not trying. No benchmark numbers are reported here because building one against the wrong mechanism would produce numbers that describe nothing real.

## Why: `provenance.py` is a declared system, same as `answerability.py` and `entitlement.py`

Every one of its three checkable mechanisms reads from an operator-registered `SourceRecord`, not from an automatic classifier run over open text:

- **`source_tier(session, key)`** (F2.1) — looks up a `key` in the database. A source nobody registered defaults to `unverified`. There is no code path that looks at a URL or a document and infers how trustworthy it is.
- **`domain_breach(record, agent_domain)`** (F2.6) — compares the source's declared **business/topical corpus** (`"finance"`, `"hr"`, `"support"`) against the agent's own declared domain. `"domain"` here is an organizational category the operator assigns at registration, not an internet domain (`bbc.com` vs. a fringe blog) — a different concept entirely from what a domain-credibility dataset scores.
- **`detect_fabricated_citations(answer, chunks)`** (F2.3) — checks whether a `[citation]` marker in the answer (a) corresponds to something in the `chunks` actually retrieved for this call, and (b) whether that chunk's own text supports the numeric figures asserted near the citation. This is **retrieval-citation-binding** (does the answer's citation resolve to something real *that was retrieved this turn*, and does that thing back up the claim) — not verification against an external, world-scale bibliographic record.

This is deliberate, and consistent with the rest of the codebase: `answerability.py`'s knowledge boundary and `entitlement.py`'s ACL grants are declared the same way, for the same stated reason (`entitlement.py`'s own docstring: *"the fact that decides the question... is not visible to the model and is not derivable from the corpus without the operator saying so"*). The trade-off is that declared systems resist benchmarking against generic public datasets, which are built to test *automatic inference*, almost by construction.

## Each candidate, checked directly

- **[HALLMARK](https://github.com/rpatrik96/hallmark) (MIT)** — fetched and inspected `data/v1.1_crossdomain_matched/test_crossdomain_matched.jsonl` directly (452 rows). Every row is a bibliographic record (`title`/`author`/`doi`/`journal`) labeled `VALID` or `HALLUCINATED` via **CrossRef DOI resolution and cross-database agreement checks** (`subtests: {doi_resolves, title_exists, authors_match, venue_correct, cross_db_agreement}`). This tests whether a cited academic paper *exists in the real world* — a capability `provenance.py` doesn't implement at all (no DOI resolution, no bibliographic lookup of any kind). Scoring it would either require building an entirely new detector (out of scope for a benchmark) or silently redefining what `detect_fabricated_citations` claims to test.
- **[CRED-1](https://github.com/aloth/cred-1) (CC-BY-4.0)** — a domain-level (internet-domain) credibility score set. Doesn't match `domain_breach`'s actual meaning of "domain" (business/topical corpus, not URL), and even setting that naming collision aside, `provenance.py` has no automatic domain-credibility inference to score against — every tier is operator-declared.
- **[ALCE](https://github.com/princeton-nlp/ALCE) (code: MIT)** — the closest conceptual fit of the three: it scores whether a citation's *source passage actually supports the claim*, which is close to what `detect_fabricated_citations`'s numeric-support check does. Investigated further and set aside for a different reason: the **data** (`princeton-nlp/ALCE-data` on Hugging Face, a separate ~450MB tarball the code repo's `download_data.sh` pulls at eval time) carries **no license tag at all** — checked directly against the HF API (`tags: ["region:us"]`, no `license` key). The code repository's MIT license doesn't extend to data hosted in a different repository with its own, unstated terms. Held back rather than used, the same treatment `docs/evaluation/dataset-sourcing.md` already gives AmbiFC for an analogous licensing gap — not rejected outright, since author confirmation could resolve it, just not usable today.

## What would actually close this gap

Matches what `docs/evaluation/dataset-sourcing.md` already concluded before any of this fetching happened: *"no dataset found matches the literal shape `NativeAclEngine.visible()` needs... adapt [a] scenario-construction methodology... over a permissively-licensed corpus, rather than waiting for the ideal dataset to appear."* The same is true here. A real F2 benchmark would need **originally-constructed scenarios** — real source documents (permissively licensed, not Wikipedia's CC-BY-SA, which this project's own license bar already excludes elsewhere), a human-authored `SourceRecord` registry with genuine tier/domain/freshness metadata, and answers with citations deliberately correct or broken in the specific ways `detect_fabricated_citations` checks for. That is meaningfully more work than every other benchmark built so far this round (all of which scored existing code against an off-the-shelf labeled dataset) and is flagged here as follow-up work requiring deliberate scenario design, not something to rush inside this pass.

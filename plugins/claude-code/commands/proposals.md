description: Review the improvement loop's change proposals, and what each one needs before it can happen
argument-hint: "[proposal-id | proposed|proven|approved|canary|applied]"
---
Load the `operate-improvement-loop` skill and follow it. Scope: $ARGUMENTS (the whole inbox
if empty; a status filters the list, an id goes straight to that proposal).

Read the evidence and the proof before recommending anything. Say which way each change
moves the control, because a loosening needs a person no matter what the evidence says. Do
not run `proposals apply` or `proposals rollback` unless the user says to in reply.

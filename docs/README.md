# Design and contributor documentation

**Using AgentFox?** The user documentation (install, quickstart, guides, CLI and API reference,
self-hosting) lives on the website at [useagentfox.com/docs](https://useagentfox.com/docs), and its
source is in [`dashboard/app/docs/`](../dashboard/app/docs/). This directory holds the material
behind the product: how it is built, why it is built that way, and how its numbers were measured.

```
docs/
├── getting-started.md   learn it: the short path, then a first hour offline
├── product-tour.md      look it up: every surface, commands by task, self-hosting
├── status.md            what is built, partial and absent (generated)
├── architecture/        how the system is put together
├── design/              what it must do, how it compares, and what is still open
├── evaluation/          how the numbers were measured, and how to read them
├── adr/                 architecture decision records
├── deployment/          running it yourself, beyond the website's self-host page
└── assets/              images used by the top-level README
```

## Start here

| Document | What it is | Who it is for |

| [getting-started.md](getting-started.md) | Teaches the product. The short path first (a key from the dashboard and `agentfox init --key`, or `agentfox scan` and `agentfox up`), then a first hour offline: initialise, scan a repo, run the demo, connect an agent over HTTP, read findings, test, turn enforcement on. Each step says what it proves. | Anyone new. |

The website splits the same material into guides. | Evaluators, and anyone looking something up. |
